# 中心认证与业务节点权限接口文档（收敛版，2026-03-07）

## 1. 文档范围

本文档只覆盖以下接口：

- 中心认证服务接口
- 业务节点接入认证后的典型接口行为
- 下载与工具执行的自动判定接口约定

本文档不覆盖：

- 完整 OAuth2/OIDC 标准实现
- 前端页面交互
- 审批工作流接口

## 2. 中心认证服务接口

### 2.1 用户注册

`POST /auth/register`

请求：

```json
{
  "username": "alice",
  "password": "123456Aa!",
  "displayName": "Alice",
  "orgCode": "3700",
  "email": "alice@example.com"
}
```

成功响应：

```json
{
  "ok": true,
  "code": "OK",
  "data": {
    "userId": "u_10001",
    "username": "alice",
    "displayName": "Alice",
    "orgCode": "3700"
  }
}
```

失败响应：

```json
{
  "ok": false,
  "code": "CONFLICT",
  "message": "username already exists",
  "data": null
}
```

### 2.2 用户登录

`POST /auth/login`

请求：

```json
{
  "username": "alice",
  "password": "123456Aa!"
}
```

成功响应：

```json
{
  "ok": true,
  "code": "OK",
  "data": {
    "accessToken": "<jwt>",
    "expiresIn": 900,
    "userInfo": {
      "userId": "u_10001",
      "username": "alice",
      "displayName": "Alice",
      "orgCode": "3700",
      "roles": ["USER"]
    }
  }
}
```

失败响应：

```json
{
  "ok": false,
  "code": "UNAUTHORIZED",
  "message": "username or password is invalid",
  "data": null
}
```

### 2.3 公钥发布

`GET /auth/public-key`

成功响应：

```json
{
  "ok": true,
  "code": "OK",
  "data": {
    "alg": "RS256",
    "publicKeyPem": "-----BEGIN PUBLIC KEY-----..."
  }
}
```

### 2.4 用户信息

`GET /auth/userinfo`

    "userId": "u_10001",
    "username": "alice",
    "displayName": "Alice",
    "orgCode": "3700",

## 3. Token 约定

`access_token` 推荐为 JWT，claims 示例：

```json
{
  "iss": "auth-center",
  "sub": "u_10001",
  "username": "alice",
  "roles": ["USER"],
  "org": "3700",
  "iat": 1741330800,
  "exp": 1741331700,
  "jti": "jwt-001"
}
```

业务节点约定：

- `currentUserId = sub`

## 4. 业务节点统一认证规则

所有业务节点接口默认要求：

- 请求头必须包含 `Authorization: Bearer <access_token>`

业务节点收到请求后：

1. 校验 JWT 签名
2. 校验过期时间
3. 解析 `sub`
4. 建立当前用户上下文

无效 token 返回：

```json
{
  "ok": false,
  "code": "UNAUTHORIZED",
  "message": "access token is invalid",
  "data": null
}
```

## 5. 业务节点对象注册与写权限

### 5.1 注册数字对象

`POST /api/v2/identifiers/register`

业务规则：

- 节点从 JWT 中解析 `currentUserId`
- 注册成功时写入 `identifier_metadata.creator_user_id = currentUserId`

### 5.2 写权限适用接口

以下接口统一按 creator 规则控制：

- `PUT /api/v2/identifiers/{identifier}/metadata`
- `PATCH /api/v2/identifiers/{identifier}/metadata`
- `DELETE /api/v2/identifiers/{identifier}`
- `PUT /api/v2/identifiers/{identifier}/component`
- `DELETE /api/v2/identifiers/{identifier}/component`
- 上传会话相关写接口

判定规则：

- `currentUserId == creator_user_id`

失败响应：

```json
{
  "ok": false,
  "code": "FORBIDDEN",
  "message": "only creator can modify this identifier",
  "data": null
}
```

## 6. 读接口规则

当前阶段约定：

- 所有已登录用户都可访问读接口

包括：

- `GET /api/v2/identifiers/{identifier}/metadata`
- `GET /api/v2/identifiers/{identifier}/object`
- `GET /api/v2/identifiers/{identifier}/component`

后续如需增强，可补充更细粒度的对象可见性控制。

## 7. 下载接口与自动判定

### 7.1 下载接口

`POST /api/v2/downloads/presign`

请求：

```json
{
  "identifier": "4201AGGG019320260307LT5XWCA3US",
  "expiresInSeconds": 300
}
```

业务规则：

1. 节点从 JWT 获取 `currentUserId`
2. 调用 `evaluateDownload(currentUserId, identifier, request)`
3. 当前阶段默认实现恒返回 `ALLOW`
4. 若对象归属远程节点，则跨节点转发，并由目标节点最终执行该判定

成功响应：

```json
{
  "ok": true,
  "code": "OK",
  "data": {
    "url": "https://storage.example.com/presign/...",
    "expiresInSeconds": 300
  }
}
```

## 8. 工具执行接口与自动判定

### 8.1 工具执行接口

`POST /api/v2/identifiers/{identifier}/tool/execute`

请求：

```json
{
  "args": {
    "a": 7,
    "b": 5
  },
  "timeoutMs": 5000
}
```

业务规则：

1. 节点从 JWT 获取 `currentUserId`
2. 调用 `evaluateToolExecute(currentUserId, identifier, request)`
3. 当前阶段默认实现恒返回 `ALLOW`
4. 若对象归属远程节点，则由目标节点最终执行判定与工具调用

成功响应：

```json
{
  "ok": true,
  "code": "OK",
  "data": {
    "identifier": "4201AGGG019320260307LT5XWCA3US",
    "operationName": "sum",
    "success": true,
    "stdout": "12\r\n",
    "stderr": "",
    "handledByNodeCode": "4201AGGG"
  }
}
```

## 9. 自动判定服务接口约定

### 9.1 下载判定

内部服务接口：

- `evaluateDownload(userId, identifier, request)`

返回示例：

```json
{
  "decision": "ALLOW",
  "reason": "permit-all-for-thesis"
}
```

### 9.2 工具执行判定

内部服务接口：

- `evaluateToolExecute(userId, identifier, request)`

返回示例：

```json
{
  "decision": "ALLOW",
  "reason": "permit-all-for-thesis"
}
```

## 10. 跨节点接口约定

当前阶段跨节点内部透传最小用户上下文：

- `userId`
- `traceId`

应用在：

- 跨节点解析
- 跨节点下载
- 跨节点工具执行
- 跨节点搜索

说明：

- 跨节点没有写操作
- 因此不需要远程 creator 写权限校验链
- 下载和工具执行的权限终审发生在目标节点

## 11. 审计建议

建议业务节点记录下列动作：

- `LOGIN`
- `REGISTER_IDENTIFIER`
- `UPDATE_METADATA`
- `DOWNLOAD`
- `TOOL_EXECUTE`
- `AUTHZ_DENY`

最小日志字段：

- `trace_id`
- `user_id`
- `action`
- `identifier`
- `node_code`
- `result`
- `reason`
- `created_at`

## 12. 最小落地实施顺序

1. 实现认证中心：`/auth/register`、`/auth/login`、`/auth/public-key`
2. 所有业务节点接入 JWT 验签
3. 在 `identifier_metadata` 增加 `creator_user_id`
4. 对象注册时写入 `creator_user_id`
5. 所有本地写接口统一接入 creator 校验
6. 新增 `RiskDecisionService`
7. 下载和工具执行统一接入自动判定，当前默认 `ALLOW`
8. 跨节点转发透传 `userId` 和 `traceId`
