# 测试文档（资源获取/下载预签名/跨节点工具执行/全网搜索，2026-03-07）

## 1. 本次覆盖范围

- 分布式解析：`RESOLVE_FORWARD`
- 分布式操作：`OP_FORWARD`
- 分布式全网搜索：`SEARCH_FORWARD`
- 搜索入口：`POST /api/v2/search/global`
- 策略对比：`RECURSIVE` 与 `ITERATIVE`

## 2. 测试拓扑

```text
country
├─ province-a
│  └─ city-a
│     └─ county-a   (入口节点)
└─ province-b
   └─ city-b
      └─ county-b   (归属节点)
```

跨分支路径（验证目标）：

- `county-a -> city-a -> province-a -> country -> province-b -> city-b -> county-b`

## 3. 核心验证点

- 资源获取可跨分支命中归属节点。
- 工具执行可跨分支命中归属节点，且返回 `handledByNodeCode`。
- 下载预签名可跨分支命中归属节点。
- 全网搜索可跨分支命中 `county-b` 注册数据。
- `country` 节点存在跨分支上层路由（nextHop 指向 `province-b`）。
- 失败断言覆盖：`ROUTE_NOT_FOUND/UPSTREAM_ERROR/TTL_EXCEEDED`。

## 7. 缺陷与修复记录

- 发现：锚点定位后进入子树搜索阶段时，锚点自身可能被 `visited` 提前命中导致 `LOOP_DETECTED`。
- 修复：子树阶段请求前，从 `visitedNodeCodes/visitedUrls` 移除锚点自身，再由锚点节点首次处理时重新加入。
- 影响：`RECURSIVE` 与 `ITERATIVE` 两种跨分支搜索均恢复稳定通过。
