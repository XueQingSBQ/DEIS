# 接口与测试用例文档_认证与权限（2026-03-07）

## 1. 启用方式

默认配置下，新鉴权能力是关闭强制校验的：

```yaml
dris:
  v2:
    auth:
      api-auth-required: false
      write-permission-enabled: false
```

如果要实际启用：

```yaml
dris:
  v2:
    auth:
      api-auth-required: true
      write-permission-enabled: true
```

## 2. 认证接口用例

### 2.1 注册

```bash
curl -X POST http://127.0.0.1:8190/auth/register \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"alice\",\"password\":\"secret123\",\"displayName\":\"Alice\",\"orgCode\":\"ABCD\"}"
```

预期：

- 返回 `200`
- `data.accessToken` 非空
- `data.userId` 非空

### 2.2 登录

```bash
curl -X POST http://127.0.0.1:8190/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"alice\",\"password\":\"secret123\"}"
```

预期：

- 返回 `200`
- `data.accessToken` 非空
- `data.tokenType == Bearer`

### 2.3 OAuth 风格 token 接口

```bash
curl -X POST http://127.0.0.1:8190/oauth2/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=password&username=alice&password=secret123"
```

预期：

- 返回 `200`
- 返回结构与 `/auth/login` 一致

### 2.4 获取公钥

```bash
curl http://127.0.0.1:8190/auth/public-key
```

预期：

- `data.algorithm == RS256`
- `data.publicKeyPem` 包含 `BEGIN PUBLIC KEY`

### 2.5 获取当前用户

```bash
curl http://127.0.0.1:8190/auth/userinfo \
  -H "Authorization: Bearer <accessToken>"
```

预期：

- 返回 `200`
- 返回 token 中的 `userId / username / orgCode`

## 3. 业务接口鉴权用例

前置：

- `api-auth-required=true`
- `write-permission-enabled=true`
- 已通过 `/auth/login` 获取 token

### 3.1 注册标识并写入 creator

```bash
curl -X POST http://127.0.0.1:8190/api/v2/identifiers/register \
  -H "Authorization: Bearer <accessToken>" \
  -H "Content-Type: application/json" \
  -d "{\"regionCode\":\"1100\",\"organizationCode\":\"ABCD\",\"industry\":\"energy\",\"dataCategory\":\"table\",\"registrationType\":\"service\",\"owner\":\"demo-owner\",\"name\":\"auth-demo\",\"entityType\":\"dataset\"}"
```

预期：

- 返回 identifier
- 数据库 `identifier_metadata.creator_user_id` 被写入当前 token 的 `sub`

### 3.2 创建人更新 metadata

```bash
curl -X PUT http://127.0.0.1:8190/api/v2/identifiers/<identifier>/metadata \
  -H "Authorization: Bearer <creatorToken>" \
  -H "Content-Type: application/json" \
  -d "{\"identifier\":\"<identifier>\",\"regionCode\":\"1100\",\"organizationCode\":\"ABCD\",\"industry\":\"energy\",\"dataCategory\":\"table\",\"registrationType\":\"service\",\"owner\":\"demo-owner\",\"status\":\"active\",\"createTime\":\"2026-03-07T00:00:00Z\",\"updateTime\":\"2026-03-07T00:00:00Z\"}"
```

预期：

- 返回 `200`
- 更新成功

### 3.3 非创建人更新 metadata

```bash
curl -X PUT http://127.0.0.1:8190/api/v2/identifiers/<identifier>/metadata \
  -H "Authorization: Bearer <otherUserToken>" \
  -H "Content-Type: application/json" \
  -d "{...}"
```

预期：

- 返回 `403`
- `code = FORBIDDEN`
- `message` 包含 `only creator can modify identifier`

## 4. 敏感读接口用例


## 6. 当前限制

- `/auth/userinfo` 只有在 `api-auth-required=true` 时才会经过拦截器解析 Bearer token
- 风险判定当前默认全部放行，仅验证链路与扩展点
- 历史数据如果 `creator_user_id` 为空，在开启 `write-permission-enabled=true` 后会被拒绝写入，需要补历史回填
