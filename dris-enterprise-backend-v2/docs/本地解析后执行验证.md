# 本地解析后执行验证（资源获取 / 服务访问 / 工具执行）

## 1. 目标

验证以下链路在单节点后端可用：

1. 通过标识解析数字对象（包含 metadata + resource）
2. 根据解析出来的 `resource.locator/extra`：
  - 获取资源数据
  - 调用服务接口
  - 执行本地工具并返回结果

## 2. 自动化用例

- 测试方法：
  - `BackendDbBusinessIntegrationTest#resolveDigitalObject_thenFetchResourceInvokeServiceExecuteTool_shouldReturnResults`
- 执行命令：

```bash
cd dris-enterprise-backend-v2
mvn -q -Dtest=BackendDbBusinessIntegrationTest#resolveDigitalObject_thenFetchResourceInvokeServiceExecuteTool_shouldReturnResults test
```

## 3. 用例设计

测试在本地启动临时 HTTP 服务（随机端口），提供两个端点：

- `GET /resource/data.json` 返回固定资源 JSON
- `GET /service/sum?a=7&b=5` 返回求和结果 JSON

然后注册 3 个标识，并分别绑定组件：

1. `resource` 组件：`locator=http://127.0.0.1:{port}/resource/data.json`
2. `service` 组件：`locator=http://127.0.0.1:{port}/service/sum`
3. `tool` 组件：`locator=local://tools/sum-cli`
   - `extra.commandWindows=["cmd","/c","set /a ${a}+${b}"]`
   - `extra.commandUnix=["sh","-lc","expr ${a} + ${b}"]`

## 4. 验证点

1. 标识解析返回对象结构完整：
- `metadata.identifier` 与注册标识一致
- `resource` 节点存在且包含 `componentType/storageType/accessMethod/locator`

2. 根据解析结果执行成功：
- 资源获取结果包含 `"value":42`
- 服务调用结果包含 `"result":12`
- 工具执行结果为 `12`

3. 用例结束后自动删除测试标识，避免污染数据。

## 5. 备注

- 当前“服务调用、工具执行”由客户端/调用方按 `resource` 信息执行（本测试在用例内模拟）。
- 后端当前负责统一存储、解析与返回资源描述；如果需要可进一步新增“服务代理调用/工具执行”后端接口。
