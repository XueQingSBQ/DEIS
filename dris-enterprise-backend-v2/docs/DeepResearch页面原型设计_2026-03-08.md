# DeepResearch 页面原型设计（2026-03-08）

## 1. 文档目标

本文档给出 `DeepResearch` 的页面布局、页面模块、视觉层次和原型草图，用于：

- 前端实现规划
- 毕设答辩页面展示设计
- 论文中的界面设计章节

## 2. 页面定位

DeepResearch 的页面不应设计成：

- 普通后台管理列表页
- 单纯聊天对话框
- 只有接口返回 JSON 的调试页

推荐定位：

`研究型工作台 + 执行轨迹台 + 证据展示台`

## 3. 总体布局

推荐采用三栏式布局。

- 左栏：输入与控制
- 中栏：执行过程
- 右栏：结果与证据

```text
+----------------------+---------------------------+-------------------------------+
| 左栏                 | 中栏                      | 右栏                          |
| 问题输入             | 研究计划                  | 结论摘要                      |
| 模板选择             | 工具调用时间线            | 对象对比表                    |
| 标识符/节点/时间筛选 | 当前执行步骤              | 资源信息卡片                  |
| 执行按钮             | 节点路径 / trace 信息     | 审计时间线 / 证据引用         |
+----------------------+---------------------------+-------------------------------+
```

## 4. 页面层级结构

### 4.1 顶部 Header

建议包含：

- 系统名称：`DRIS DeepResearch`
- 当前用户
- 当前环境标记：`demo / test / prod`
- 当前研究会话标题
- 导出按钮

### 4.2 左侧 Control Panel

建议模块：

- 研究问题输入框
- 快捷模板列表
- 标识符输入区
- 节点范围选择器
- 时间范围选择器
- 研究模式选择器
- 执行按钮
- 清空按钮

### 4.3 中间 Execution Panel

建议模块：

- 自动生成的研究计划
- 工具调用状态时间线
- 当前步骤详情
- 节点跳转路径图
- 工具输入/输出摘要

### 4.4 右侧 Insight Panel

建议模块：

- 结论摘要卡片
- 关键发现列表
- 数字对象对比表
- 资源定位信息卡片
- 审计时间线
- 证据引用面板

## 6. 页面模块详细设计

### 6.1 QuestionInputPanel

作用：

- 接收自然语言研究问题
- 支持粘贴多个标识符
- 作为整个页面的入口

建议字段：

- `question`
- `identifierList`
- `nodeScope`
- `timeRange`
- `templateId`

### 6.2 ResearchTemplatePanel

作用：

- 降低用户输入难度
- 适合答辩演示快速切换场景

建议模板：

- 跨节点对象研究
- 资源可用性分析
- 对象来源与审计分析
- 指定标识深度报告

### 6.3 ResearchPlanPanel

作用：

- 展示系统自动规划出的执行步骤
- 让用户知道系统在做什么

建议显示：

- 步骤序号
- 步骤名称
- 对应 MCP Tool
- 预计输入对象
- 当前状态

### 6.4 ToolTimelinePanel

作用：

- 展示真实的工具调用过程
- 体现 AI 调用不是黑箱

建议字段：

- `toolName`
- `status`
- `startTime`
- `durationMs`
- `traceId`
- `targetNode`

### 6.5 NodePathPanel

作用：

- 直观展示跨节点路径
- 体现 DRIRP 分布式解析能力

建议展示方式：

- 简单链路图
- 节点卡片 + 箭头
- 每个节点显示成功条数/失败条数

### 6.6 SummaryPanel

作用：

- 给出最终简洁结论
- 适合汇报和截图

建议内容：

- 总对象数
- 成功解析数
- 失败数
- 关键差异点
- 风险提示

### 6.7 ComparisonPanel

作用：

- 并排比较多个对象的元数据、对象状态和资源情况

建议列：

- `identifier`
- `targetNodeCode`
- `resolvedByNodeCode`
- `metadata.name`
- `status`
- `revision`
- `resource.componentType`
- `resource.locator`
- `auditLatestOperation`

### 6.8 AuditTimelinePanel

作用：

- 展示对象的审计记录和变更轨迹

建议字段：

- 时间
- 操作类型
- 是否成功
- 操作者
- 说明

### 6.9 EvidencePanel

作用：

- 展示结论背后的证据来源
- 适合答辩强调“可追溯”

建议字段：

- `sourceType`
- `sourceTool`
- `identifier`
- `nodeCode`
- `traceId`
- `excerpt`

## 7. 页面状态设计

页面建议区分以下状态：

- 空白状态
- 规划中状态
- 执行中状态
- 成功状态
- 部分成功状态
- 失败状态

### 7.1 空白状态

显示：

- 示例问题
- 研究模板卡片
- 最近研究记录入口

### 7.2 执行中状态

显示：

- loading 进度条
- 当前工具名称
- 当前访问节点
- 已完成步骤数

### 7.3 部分成功状态

显示：

- 黄色警示条
- 局部失败条目列表
- 仍然展示已完成部分结果

## 9. 移动端适配建议

虽然主要演示场景在桌面端，但页面仍应兼容移动端。

建议：

- 三栏改为纵向堆叠
- 顶部保留问题输入与执行按钮
- 过程与结果用 Tab 切换
- 证据和时间线折叠展示

## 10. 视觉方向建议

为了避免页面过于像后台管理系统，建议视觉方向如下：

- 以“研究台、控制台、证据板”为视觉语言
- 采用浅色底 + 高对比信息卡片
- 过程区使用时间线与步骤块
- 结果区使用卡片、表格、标签、时间线结合
- 节点路径图使用少量高亮色强调路由方向

建议主色：

- 深蓝灰：主结构色
- 青绿色：成功执行与有效结果
- 橙黄色：局部失败与风险提示
- 红色：失败与异常

## 11. 答辩展示最佳截图位

建议准备以下页面截图：

- 首页空白状态
- 执行中状态
- 批量解析完成状态
- 局部失败状态
- 最终研究报告页

## 12. 与后端能力的对应关系

页面中的主要展示块对应后端能力如下：

- 研究候选对象区 -> `POST /api/v2/search/global`
- 元数据/对象/资源对比区 -> 三个批量分布式解析接口
- 审计时间线 -> `GET /api/v2/audit/identifier-history`
- 节点路径区 -> `GET /api/v2/node/routes`

## 13. 实施优先级建议

优先级 1：

- 首页输入区
- 研究计划区
- 工具时间线区
- 结果摘要区

优先级 2：

- 对象对比表
- 资源卡片
- 审计时间线

优先级 3：

- 节点路径图
- 证据引用面板
- 报告导出

## 14. 结论

DeepResearch 的页面设计重点不在“页面多”，而在“让老师一眼看到系统正在研究问题，并且研究过程和结论都基于你现有数字对象系统的真实能力”。

因此最重要的三个展示要素是：

- 任务输入
- 执行轨迹
- 证据化结果
