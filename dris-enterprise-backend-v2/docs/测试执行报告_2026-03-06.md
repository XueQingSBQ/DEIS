## 4. 关键场景结论

1. COS 上传链路可用
- `resource`、`tool`、`service` 三类 profile 均可创建 upload session 并完成提交
- 返回上传地址包含 COS bucket 域名

2. 工具/服务可直接绑定（不上传对象仓库）
- `tool` 支持 `storageType=local_exec`、`accessMethod=invoke`、`locator=local://...`
- `service` 支持 `storageType=api_service`、`accessMethod=api_call`、`locator=https://...`
- 支持把操作说明、参数模板、输入输出 schema 放入 `extra`

3. 解析后执行链路可用
- 通过 `/api/v2/identifiers/{id}/object` 可拿到完整数字对象（metadata + resource）
- 根据解析出的 `resource.locator` 可读取资源数据
- 根据解析出的服务 `locator` 可完成服务访问并拿到返回
- 根据解析出的工具 `extra` 命令模板可执行本地工具并返回结果

## 5. 本次关键修复（与测试相关）

- 修复了直绑组件时 JDBC 落库空值兼容：
  - `role/hashValue/etag/versionId/createdAt` 空值统一归一化，避免历史表结构 `NOT NULL` 报错
- 修复了服务上传会话 `expected_sha256` 空值兼容，避免旧库 `NOT NULL` 冲突
- 扩展了 `upload_session.component_type` 约束，允许 `service`
