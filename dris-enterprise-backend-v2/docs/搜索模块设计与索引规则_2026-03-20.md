# 搜索模块设计与索引规则

## 1. 目标

当前系统的本地检索与 ES 检索已经具备可用性，但字段范围偏宽，资源技术字段、状态字段和补充属性原始文本同时参与搜索，容易带来以下问题：

- 检索噪声偏大，结果相关性不稳定
- 标识元数据与资源访问字段混杂，排序可解释性不足
- 本地检索和 ES 检索权重口径不一致，结果不易统一

本次调整的目标是将搜索模块收敛为“面向标识元数据的生产级检索”：

- 只对标识元数据建立主搜索索引
- 将补充字段统一收敛到 `additionalAttributes`
- 将模糊召回字段与精准过滤字段分开
- 通过结果截断规则去除尾部低质量结果

## 2. 字段范围

### 2.1 原生字段

原生注册字段保留如下：

- `identifier`
- `name`
- `description`
- `applicationScenario`
- `owner`
- `industry`
- `dataCategory`
- `registrationType`
- `entityType`

### 2.2 补充字段

补充字段统一放入 `additionalAttributes`，仅保留以下四项：

- `column`：主题/栏目分类
- `region`：地区文本
- `keywords`：业务关键词数组
- `sourceFilename`：原始文件名

其中搜索投影关系如下：

- `theme <- additionalAttributes.column`
- `region <- additionalAttributes.region`
- `bizKeywordsText <- additionalAttributes.keywords`
- `sourceFilename <- additionalAttributes.sourceFilename`

## 3. 索引策略

### 3.1 全文主召回字段

主召回字段及权重顺序固定为：

`theme > region > name > keywords > description > applicationScenario`

建议基础权重如下：

- `theme`: 10
- `region`: 8
- `name`: 6
- `bizKeywordsText`: 5
- `description`: 4
- `applicationScenario`: 4

说明：

- `theme` 用于体现文档主题类别，是最重要的主题信号
- `region` 用于体现区域约束，在水利业务场景中权重应高
- `name` 保留较高权重，但不高于主题和地区
- `keywords` 作为补充业务词召回
- `description` 与 `applicationScenario` 只做语义补充

### 3.2 精准过滤字段

以下字段只用于过滤或精确匹配，不参与主全文权重：

- `identifier`
- `industry`
- `dataCategory`
- `registrationType`
- `entityType`

其中：

- `identifier` 用于唯一定位和精确命中
- `industry`、`dataCategory`、`registrationType`、`entityType` 用于结构化过滤

### 3.3 辅助字段

以下字段不作为主召回核心字段，但可以参与展示或弱辅助：

- `owner`
- `sourceFilename`

说明：

- `owner` 保留弱权重，避免机构名压过业务主题
- `sourceFilename` 仅用于辅助召回和结果展示，不应主导排序

### 3.4 排除字段

以下字段不再进入主搜索索引，也不再参与本地主评分：

- `status`
- `updateTime`
- `componentType`
- `storageType`
- `accessMethod`
- `contentType`
- `format`
- `locator`
- `additionalAttributesText` 原始整块 JSON

原因是这些字段属于状态或资源技术实现信息，会显著放大搜索噪声。

## 4. 查询规则

### 4.1 默认策略

默认检索采用“模糊召回优先，结构化过滤可选”的方式：

1. 优先使用 `theme`、`region`、`name`、`bizKeywordsText`、`description`、`applicationScenario` 做模糊召回
2. 当请求显式传入结构化过滤字段时，再叠加精确过滤
3. 不强制要求每个查询都命中精准字段

### 4.2 phrase 加分

为提升标题型查询和类别型查询的准确度，保留以下短语加分：

- `theme` 短语命中强加分
- `region` 短语命中高加分
- `name` 短语命中高加分
- `bizKeywordsText` 短语命中中等加分

## 5. 结果截断规则

搜索接口可召回最多 5 条候选，但最终返回结果需要经过二次裁剪。

建议规则如下：

1. 先按 ES 或本地评分完成候选排序
2. 最多保留前 5 条候选
3. 结果分数低于第一名的 60% 时丢弃
4. 若相邻结果出现明显断崖下跌，则从断崖处截断
5. 若结果仅命中弱字段，未命中 `theme`、`region`、`name` 任一核心字段，则降权或丢弃

这样可以满足“上限返回 5 条，但高质量结果通常只返回 2 至 3 条”的业务需求。

## 6. 实现收敛要求

### 6.1 ES 检索

- ES 只建立标识元数据索引
- `theme`、`region`、`name`、`bizKeywordsText`、`description`、`applicationScenario` 为主检索字段
- `identifier`、`industry`、`dataCategory`、`registrationType`、`entityType` 作为过滤字段
- 移除资源技术字段和 `status`

### 6.2 本地检索

- 本地评分公式与 ES 字段顺序保持一致
- 本地预取可继续从 `additional_attributes` 中取候选，但最终评分必须基于投影后的 `theme`、`region`、`bizKeywordsText`
- 本地过滤字段与 ES 过滤字段保持一致

## 7. 补充字段示例

```json
{
  "column": "技术标准",
  "region": "湖南省岳阳市平江县",
  "keywords": ["山洪灾害", "分析评价", "技术要求", "小流域"],
  "sourceFilename": "山洪灾害分析评价技术要求.pdf"
}
```

## 8. 本次改造范围

本次代码改造重点覆盖：

- ES mapping 与 query 字段收敛
- 本地检索评分逻辑收敛
- 本地过滤字段收敛
- 结果排序与截断规则补充

不包含：

- 时间字段检索
- 复杂同义词体系
- 多模态资源搜索规则
