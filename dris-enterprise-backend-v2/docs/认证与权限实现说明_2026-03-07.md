# 认证与权限实现说明（2026-03-07）

## 1. 实现目标

本次实现只落地最小可用的认证与权限能力，尽量降低对现有代码和 SDK 的耦合：

- 新增中心认证接口：注册、登录、取公钥、取当前用户信息
- 新增 JWT 鉴权拦截能力
- 在 `identifier_metadata` 增加 `creator_user_id`
- 标识注册成功后回填 `creator_user_id`
- 本地写操作仅允许创建人执行
- 下载、工具执行增加 `RiskDecisionService` 钩子
- 跨节点下载、工具执行转发时透传 `userId`

明确没有做的内容：

- 不改 `dris-java-sdk` 写入路径
- 不增加复杂 ACL / ABAC
- 不增加跨节点写授权
- 风险判定当前默认全部放行，仅预留接口

## 3. 数据库变更

### 3.1 `identifier_metadata`

新增字段：

- `creator_user_id VARCHAR(64)`

作用：

- 只用于本地写权限控制
- 不替代现有 `owner`
- 不向外暴露更多用户隐私信息

### 3.2 `iam_user`

新增字段：

- `password_hash VARCHAR(255)`

作用：

- 中心认证服务存储密码哈希

## 4. 配置项

在 `application.yml` 中新增：

```yaml
dris:
  v2:
    auth:
      api-auth-required: false
      write-permission-enabled: false
      issuer: auth-center
      audience: dris-business-node
      access-token-ttl-seconds: 7200
      key-id: dris-v2-auth-rs256
      key-seed: dris-v2-auth-center-key-seed
```

说明：

- `api-auth-required=false`
  - 默认关闭业务接口强制鉴权，避免影响现有测试和联调
- `write-permission-enabled=false`
  - 默认关闭创建人写权限强校验，兼容旧数据
- 推荐在启用认证时同时设为 `true`

## 5. 权限行为

### 5.1 注册

- 调用 `drisClient.generateIdentifier(request)`
- 注册成功后，由 `IdentifierPermissionService` 通过 DAO 回填 `creator_user_id`
- 未改 SDK 内部仓储逻辑

### 5.2 本地写权限检查

以下路径增加创建人检查：

- `IdentifierCoreService.updateIdentifier`
- `IdentifierCoreService.partialUpdateIdentifier`
- `IdentifierCoreService.deleteIdentifier`
- `IdentifierResourceService.upsertComponent`
- `IdentifierResourceService.removeComponent`
- `IdentifierUploadService.createUploadSession`
- `IdentifierUploadService.completeUpload`

判定规则：

- `currentUserId == creator_user_id` 允许
- 否则返回 `403 FORBIDDEN`

### 5.3 下载 / 工具执行

- 本地调用前先执行 `RiskDecisionService`
- 当前实现是 `PermitAllRiskDecisionService`
- 后续可以替换为真正的风险评估或审批策略

## 6. 跨节点透传

在 `OperationForwardRequestPayload` 新增：

- `userId`

用途：

- 入口节点发起下载 / 工具执行时，把当前用户 `sub` 透传给目标节点
- 目标节点本地落点执行风险判断时，可以拿到真实用户身份

当前透传范围：

- `DOWNLOAD_PRESIGN`
- `TOOL_EXECUTE`

## 7. 低耦合设计点

本次实现刻意保持低耦合：

- 未修改 `dris-java-sdk`
- 创建人绑定采用“注册成功后本地更新”方式
- 鉴权采用自定义 MVC 拦截器，没有引入整套 Spring Security Filter Chain
- 风险控制使用独立接口，当前默认放行，后续可替换实现
